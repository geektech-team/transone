# 组件选择报告、异常清理与构建输出回滚

日期：2026-10-29。范围来自用户明确要求；下述 API 名称和实现细节是本次实现选择。

## 目标

1. 解释逻辑组件如何匹配具体端、通用平台族或业务基类，提供人类可读及结构化报告。
2. 生命周期、子组件或自定义清理函数抛错时，继续清理其余资源，并保留可定位的错误。
3. Web、小程序、App 和库构建失败时，保留上一版完整产物；成功后再发布新输出。

保持现有平台匹配顺序：具体端实现 → 同族通用实现 → 可实例化业务基类。保留显式实现引用、旧命令与配置兼容性。

## 组件报告

- 共享组件索引提供同一份匹配决策，选择与报告不各自实现优先级。
- `reportComponents(options)` 是只读 API；`transone build --report-components` 在正常构建前输出报告。
- 每行包含规范化具体端、入口上下文、逻辑组件及实现的文件/类/位置、匹配原因和可用候选。
- Web 按入口报告，与每入口构建索引一致；小程序/App 使用其实际共享页面索引。报告与构建复用同一份解析后配置。
- 报告范围是静态发现的逻辑组件映射，不声称证明运行时可达性。未使用的抽象类可显示缺少实现，不因此单独阻止报告。
- 不执行组件模块，不创建构建目录；项目配置按既有配置加载契约处理。库构建与应用组件报告组合明确拒绝。

## 异常清理

- 组件提供 `onDispose(cleanup)` 注册自定义清理，返回撤销注册函数；采用 FIFO 顺序。
- 卸载应幂等并防止重入。一个钩子、子组件或清理函数失败，不阻断其他清理；清空组件/应用状态及自身拥有的全局引用。
- 单个错误保留原对象；多个错误汇总为 `AggregateError`。应用保留现有日志式异常契约。
- 初次挂载失败也释放已创建的资源。渲染器卸载遍历使用稳定快照，避免 DOM 移除造成遗漏兄弟节点。
- 请求无论成功、失败、取消、超时或宿主同步回调/抛错，均释放外部取消监听与定时器。宿主 abort 缺失、抛错或不回调也能结束请求。
- 不调整构造器初始化顺序，不扩展原生 App 的静态编译能力。

## 输出回滚

- 写入独占的同级临时目录；编译、文档渲染、声明文件生成和静态资源复制均完成后再切换。
- 先校验真实最终目的地及受保护输入路径，不能因临时目录重定向而绕过原有保护。
- 发布时保留独占备份。切换失败恢复旧目录；恢复失败保留可恢复备份并报告其位置。
- 只清理本次拥有的临时目录。成功发布后的备份清理失败作为警告，避免将已发布的新产物误报为构建失败。
- 同一进程内对同一目的地的并发构建正确协调；结果返回最终目录与资产路径，HTML/CSS/声明引用可用。
- 本轮保证进程内异常恢复，不承诺断电或进程强制终止时的目录交换原子性。

## 验收

- 真实源码夹具验证精确/通用/基类/缺失匹配、别名、冲突、只读报告和 CLI 输出。
- 验证卸载抛错后的兄弟与资源清理、应用状态、清理顺序/重入、请求全部结算路径。
- 文件系统故障验证旧输出不变、无首次半成品、成功替换、发布回滚、临时目录回收与并发协调。
- 包构建、生成项目及文档验证；完整测试最后串行运行，监听用例使用允许回环端口的环境。
- 既有全仓类型问题与本次新增诊断分别报告；生成工程验证不等同原生 SDK/真机验收。
